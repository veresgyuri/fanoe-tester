## 4. Output & Delivery
- **Complete code first:** Provide fully functional, usable code by default. No partial snippets or "pseudocode."  
- **Minimal edits:** If modifying existing code, change only what is necessary. Avoid refactoring unrelated code.  
- **Validation:** Always validate generated code against the `CODE GENERATION LOGIC` section in relevant `/instructions/*.md` file before delivery.  
- **Testing notes:** Include comments or test suggestions for new hardware-related modules to aid debugging via Serial REPL.

## 5. Coding Standards & Style
- **Pattern:** Use modular, Object-Oriented Programming (OOP) patterns for `code.py` and other logic modules.  
`menu_data.py` is a pure data file (menu tree structure) and is NOT subject to the OOP requirement — it must remain a plain,  
directly-readable data structure (dict/list), with no embedded function calls or live references.  
Dynamic screens reference an "action" string key, resolved/dispatched by code.py.
- **Naming:** snake_case for variables/functions, PascalCase for classes.  
- **Formatting:** 4 spaces indentation, max 88 characters per line (Black style).
- **Libraries:** Only use CircuitPython-compatible libraries  
- **Memory Management:** Prioritize stability; minimize global variables and release unused resources.  
- **Documentation:** Use clear, concise comments and docstrings. Maintain readability for DIY hobbyists.
- **Error Handling:** Implement robust error handling with try-except blocks, especially for hardware interactions and network operations.
- **Logging & Debugging:** Use a global `DEBUG` flag and a `dprint(*args, **kwargs)` wrapper to gate all non-critical REPL output.

## 6. Display & Keypad Logic
- **Non-Blocking Execution:** UI updates (TFT) and input handling (Keypad) MUST NOT interrupt the measurement. Use asyncio or non-blocking state machines.
- **Validation:** Include print() or logging statements for key state changes (analog input, GPIO level, errors) to assist debugging via Serial REPL.
- **Setting Management:** Implement a modular settings management system that can easily add/remove settings from `settings.toml` without code changes.
- **Stability:** This board has 2MB embedded PSRAM. CircuitPython automatically places large allocations (e.g. displayio bitmaps, buffers) there once the firmware build supports PSRAM — no manual memory placement is needed in code. Still keep UI/menu logic memory-conscious: avoid unnecessary large temporary buffers, and release unused objects (del + gc.collect()) after heavy operations like display redraws.

## 7. Testing & Deployment
- **Unit Testing:** Suggest basic test cases for new hardware-related modules.
- **Manual Deployment:** Keep in mind that code is deployed by copying files to the CIRCUITPY drive; avoid any automation scripts for file transfer.
